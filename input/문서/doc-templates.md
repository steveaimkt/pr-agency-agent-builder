# 문서 템플릿 세트 (기본값)

> 이 파일이 스킬의 **문서 양식 창고**다. `doc-studio` 의 ⚙️ 개조 포인트 3이 이 파일을 가리킨다.
> 모듈 1(회의록)과 모듈 3(문서 초안)이 이 파일을 읽어서 문서를 만든다.
> 여기 있는 3종은 **기본 양식**일 뿐이다. 실습 2에서 각자 자기 팀이 실제로 쓰는 양식으로 갈아끼운다.
>
> 규칙 하나. **양식의 칸을 채우지 못하면 비워두고 `[확인 필요]` 를 남긴다.** 지어내지 않는다.

## 템플릿 1 · 회의록 (모듈 1이 쓴다)

클라이언트 미팅 직후에 쓴다. 30분 안에 클라이언트에게 보내는 것이 목표다.
**"들은 것"과 "정한 것"과 "할 것"을 분리하는 것이 이 양식의 전부다.**

```markdown
# {클라이언트} {회의명} 회의록

- 일시 : {YYYY-MM-DD (요일) HH:MM ~ HH:MM}
- 장소 : {장소}
- 참석 : {클라이언트 측 이름·직함} / {대행사 측 이름·직함}
- 작성 : {작성자} · {작성일}

## 1. 논의 요약 (3줄)
{이 미팅에서 무슨 일이 있었는지 3줄. 시간 순이 아니라 중요도 순}

## 2. 결정사항
| # | 결정된 것 | 근거·맥락 | 확정 여부 |
|---|---|---|---|
| D1 | {한 문장} | {왜 이렇게 정했나} | 확정 / 잠정 |

## 3. To-Do
| # | 할 일 | 담당 | 기한 | 연결 결정 |
|---|---|---|---|---|
| T1 | {동사로 끝나는 한 문장} | {이름} | {YYYY-MM-DD} | D1 |

## 4. 미확정 · 확인 필요
| # | 항목 | 누구에게 확인 | 언제까지 |
|---|---|---|---|
| C1 | {숫자·날짜·담당이 비어 있는 것} | {이름} | {YYYY-MM-DD} |

## 5. 다음 미팅
{일시} · {장소} · {주요 안건}
```

**칸 설명 (스킬이 지키는 규칙)**

| 칸 | 규칙 |
|---|---|
| 결정사항 | **"~하기로 했다"로 끝나야 결정이다.** "~하면 좋겠다", "~를 검토 중이다"는 결정이 아니라 논의다. 논의를 결정 칸에 올리지 않는다 |
| 결정 확정 여부 | 양측이 명시적으로 합의한 것만 `확정`. 한쪽만 말하고 끝난 것은 `잠정` |
| To-Do 담당 | **담당이 안 정해진 할 일은 담당 칸을 비우고 4번 표로 올린다.** 추측해서 이름을 넣지 않는다 |
| To-Do 기한 | 날짜가 없으면 "7월 셋째 주" 같은 원문 표현을 그대로 두고 4번 표로 올린다 |
| 미확정 | **금액, 날짜, 인원 같은 숫자가 안 나온 항목은 전부 여기로.** 회의록에서 가장 값진 표다 |
| 잡담 | 근거 없는 소문, 잡담은 회의록에 넣지 않는다 |

## 템플릿 2 · 주간 보고 (모듈 3이 쓴다)

매주 금요일, 디렉터에게 낸다. **A4 1장을 넘기지 않는다.**

```markdown
# {팀명} 주간 보고 · {YYYY-MM-DD} ~ {YYYY-MM-DD}

작성 : {AE 이름}

## 1. 이번 주 한 줄
{이번 주에 가장 중요했던 사실 한 문장}

## 2. 클라이언트별 진행
| 클라이언트 | 이번 주 한 일 | 상태 | 다음 주 |
|---|---|---|---|
| {클라이언트} | {완료된 것만. 진행 중은 상태 칸에} | 정상 / 지연 / 이슈 | {한 문장} |

## 3. 숫자
| 항목 | 이번 주 | 지난 주 | 비고 |
|---|---|---|---|
| 보도자료 배포 | {n}건 | {n}건 | |
| 언론 노출 | {n}건 | {n}건 | |
| {팀 지표} | | | |

## 4. 막힌 것 (디렉터 도움이 필요한 것)
- {한 줄. 없으면 "없음"이라고 쓴다. 비워두지 않는다}

## 5. 다음 주 우선순위 3개
1. {}
2. {}
3. {}
```

**칸 설명**

| 칸 | 규칙 |
|---|---|
| 상태 | `정상 / 지연 / 이슈` 3개만 쓴다. "거의 다 됐음" 같은 표현을 쓰지 않는다 |
| 숫자 | **원자료에서 센 것만 적는다.** 감으로 적지 않는다. 원자료가 없으면 `데이터 없음` |
| 막힌 것 | **주간 보고에서 디렉터가 유일하게 정독하는 칸이다.** 없으면 "없음"이라고 명시한다 |

## 템플릿 3 · 이슈 리포트 (모듈 3이 쓴다)

부정 기사, 클레임, 사고가 터졌을 때 **1시간 안에** 쓴다. 클라이언트와 디렉터에게 동시에 간다.
길게 쓰지 않는다. 사실과 사실 아닌 것을 가르는 것이 목적이다.

```markdown
# [이슈] {한 줄 제목} · {YYYY-MM-DD HH:MM 기준}

## 1. 무슨 일인가 (사실만)
- 최초 인지 : {YYYY-MM-DD HH:MM} · {인지 경로}
- 발생 : {매체·채널} · {제목} · {URL}
- 확산 : {현재까지 관련 보도 n건 / 커뮤니티 확산 여부}

## 2. 확인된 사실 vs 확인 안 된 것
| 확인된 사실 | 아직 확인 안 된 것 |
|---|---|
| {출처와 함께} | {누구에게 확인 중인지 함께} |

## 3. 영향 판단
| 항목 | 판단 | 근거 |
|---|---|---|
| 위험도 | 상 / 중 / 하 | |
| 확산 가능성 | 상 / 중 / 하 | |
| 클라이언트 고지 | 완료 / 필요 / 불필요 | |

## 4. 지금 하는 것 (진행 중)
| # | 조치 | 담당 | 완료 예정 |
|---|---|---|---|

## 5. 판단이 필요한 것 (사람이 정한다)
- {대응 수위, 입장문 발표 여부 등. AI가 정하지 않는다}
```

**칸 설명**

| 칸 | 규칙 |
|---|---|
| 확인된 사실 | **출처가 붙지 않는 문장은 이 칸에 넣지 않는다.** 반대편 칸으로 보낸다 |
| 위험도 | 판단은 초안이다. **사람이 확정한다** |
| 5번 | 이 칸이 비어 있으면 이슈 리포트가 아니다. 대응 수위는 언제나 사람이 정한다 |

## 이 파일을 갈아끼우는 법 (실습 2)

1. 내 팀이 실제로 쓰는 회의록 양식(한글 파일이든 노션이든)을 연다
2. 위 템플릿 1의 `## 2. 결정사항` 같은 **섹션 제목만** 내 양식 이름으로 바꾼다
3. 우리 팀에 없는 섹션은 지운다. 우리 팀에만 있는 섹션(예: "클라이언트 반응 온도")은 추가한다
4. 저장하고 스킬을 다시 부른다. 다음 회의록부터 **내 팀 양식으로** 나온다

⚠ 템플릿을 바꿔도 **"칸 설명"의 규칙은 지우지 않는다.** 특히 이 셋은 남긴다.
`결정 아닌 것을 결정에 올리지 않는다` / `담당을 추측하지 않는다` / `없는 숫자를 지어내지 않는다`
