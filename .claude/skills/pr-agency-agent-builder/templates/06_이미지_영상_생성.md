# 트랙 06 · 이미지·영상 생성

> 대행사에서 자주 나오는 업무 · "이미지·영상 생성" (많이 고르는 순서 6위)
> 갈래 · 콘텐츠 · 권장 그릇 · **스킬** (콘셉트를 받아 시안을 만드는 절차가 고정돼 있고, 판단은 확인 단계 몇 개뿐이다)

## 병목 · 어디서 시간이 가나
- 제작팀이 콘셉트를 받아 이미지·영상 시안을 여러 개 뽑는 작업 자체는 빠르다. 시간이 가는 곳은 그 다음이다. 시안마다 **상업 사용 조건**을 생성 도구 약관에서 다시 찾아봐야 한다.
- 시안에 실존 인물이나 실존 브랜드 로고와 닮은 요소가 섞여 나오는지 눈으로 하나씩 확인해야 한다. 놓치면 고객사 전달 후 사고가 된다.
- 생성물이라는 표기를 붙일지 말지가 캠페인마다 다른데, 이 합의를 매번 새로 확인하느라 전달이 늦어진다.
- 시안을 여러 개 만들다 보면 어느 시안이 어느 도구, 어느 조건으로 만들어졌는지 기록이 사라진다. 나중에 확인하려 하면 처음부터 다시 찾아야 한다.

## 입력 / 출력
- **입력** · 콘셉트 브리프(브랜드 보이스, 캠페인 브리프), 참고 이미지(있으면)
  참고 이미지에 실존 인물이 들어 있으면 그 사실을 미리 표시해 둔다. 점검 단계에서 놓치지 않기 위해서다.
- **출력** · 이미지·영상 시안 여러 장 + 상업 사용 조건 확인 결과 + (합의된 경우) 생성물 표기
  확인이 끝나지 않은 시안과 확인이 끝난 시안은 폴더를 따로 둔다. 섞어 두면 실수로 넘어간다.

## 판단 룰 (숫자로 못박는다)
저작권과 초상권은 이 트랙에서 제일 먼저 보는 기준이다. 아래 셋 중 하나라도 걸리면 넘기지 않는다.
- **상업 사용 조건을 확인하기 전에는 고객사에 넘기지 않는다.** 확인 전 시안은 내부 검토용으로만 쓴다.
- **실존 인물의 얼굴, 실존 브랜드의 로고·상표를 생성하지 않는다.** 인물이 필요하면 가상 인물로 만들거나 실제 촬영본을 쓴다.
- **생성물임을 표기할지는 고객사와 합의한 뒤에만 정한다.** 합의 전에는 표기를 임의로 넣거나 빼지 않는다.
- 시안 하나마다 사용한 생성 도구 이름과 확인한 상업 사용 조건을 **로그 한 줄**로 남긴다. 나중에 어느 조건으로 만들었는지 되짚을 수 있어야 한다.

## 스텝 초안 (5~7)
| 스텝 | 입력 → 처리 → 출력 | 담당 |
|---|---|---|
| 1 | 콘셉트 브리프 확인 → 시안 방향 메모 | AI |
| 2 | 이미지·영상 시안 여러 개 생성 | AI |
| 3 | 시안마다 실존 인물·실존 로고 유사 요소 자체 점검 | AI |
| 4 | 사용한 생성 도구의 상업 사용 조건 확인 | AI |
| 5 | 생성물 표기 여부를 고객사와 합의했는지 확인 | 사람 |
| 6 | 담당자 최종 승인 → 고객사 전달 폴더로 이동 | 사람 |
| 7 | 사용한 도구, 조건 확인 결과 로그 저장 | AI |

## 사람 개입 게이트
- **저작권·초상권 게이트** · 상업 사용 조건과 실존 인물·로고 여부를 담당자가 확인한 뒤에만 고객사 전달 폴더로 옮긴다. 확인이 끝나지 않은 시안은 전달하지 않는다.
- 생성물 표기 여부를 고객사와 합의했는지 담당자가 확인한 뒤 전달한다.
- 캠페인 콘셉트와 다른 방향의 시안이 나왔을 때는 담당자가 방향을 다시 정하고, AI가 그 방향으로 다시 만든다.

## 도구
- **읽기** · 브랜드 보이스, 캠페인 브리프, 생성 도구 약관을 연다. 시안은 이미지·영상 생성 도구로 뽑는다
- **만들기** · 중간 산출물은 `.md` 로 만든다. 고치기 쉽고 다시 돌리기 쉽다
- **내보내기** · 마지막에 형식을 고른다. 이 트랙에 맞는 것은 **웹 화면** 이다. 시안을 나란히 놓고 보는 자리라서 그렇다
  | 고르면 | 무엇으로 | 언제 |
  |---|---|---|
  | 파워포인트 | 공식 스킬 `pptx` | 발표하거나 고객사에 보고할 때 |
  | 워드 | 공식 스킬 `docx` | 문서로 넘기고 상대가 고쳐 써야 할 때 |
  | 엑셀 | 공식 스킬 `xlsx` | 표와 숫자가 본체일 때 |
  | 웹 화면 | `tools/md2html.py` | 빨리 보고 링크로 돌려볼 때 |
- **디자인** · 색과 글꼴을 새로 고르지 않는다. `design-system/colors_and_type.css` 를 물리고,
  장표는 `tools/slide-design.md`, 문서는 `tools/design.md` 규격 그대로 간다. 형광은 한 장에 한 번만
- **검산** · 시안마다 사용한 생성 도구 이름과 확인한 상업 사용 조건을 로그 한 줄로 남기고, 시안 수와 로그 줄 수가 맞는지 센다
- 저작권 확인 · 상업 사용 조건과 실존 인물·로고 여부를 확인하기 전에는 고객사 전달 폴더로 옮기지 않는다. 확인 결과는 로그로 남긴다

## 샘플 자료 · 내 파일이 없으면 이걸로 시작한다
- `input/콘텐츠/brand-voice.md` · 콘셉트의 톤을 맞출 때 참고하는 브랜드 보이스 파일이다.
- `input/콘텐츠/campaign-brief.md` · 시안이 따라야 할 캠페인 핵심 메시지와 근거가 들어 있다.
- 내 업무 파일이 있으면 그것부터 쓴다. 위 샘플은 파일이 없을 때만 쓰는 연습용이다.

## 자주 나오는 함정
- 생성 도구가 무료로 만들어 준 이미지라고 바로 상업 사용이 가능하다고 착각하는 것. 무료와 상업 사용 가능은 다른 문제다.
- 참고 이미지로 넣은 실존 인물 사진이 결과물에 닮은꼴로 그대로 남는 것. 결과물이 실존 인물처럼 보이는지 한 번 더 확인한다.
- 시안이 마음에 든다고 저작권·초상권 확인을 건너뛰고 바로 전달하는 것. 마음에 드는 시안일수록 확인을 먼저 한다.
- 콘셉트를 받아 시안을 만들고 확인하는 순서를 캠페인마다 다르게 잡는 것. 순서는 고정하고 콘셉트만 바꾼다. 그래서 이 트랙은 에이전트보다 스킬이 맞다.
