# 업무 구체화 워크시트 (누구나 · 빈칸만 채우면 된다)

> 자동화할 업무가 막막해도, 이 8칸을 위에서 아래로 채우면 에이전트 설계가 완성된다.
> 스킬이 한 칸씩 같이 채워준다. 혼자 할 때는 A→H 순서로 적으면 된다.

## 📘 이 워크시트가 뭔가요? (처음이면 먼저 읽기)

**한 줄 비유:** 워크시트는 **에이전트에게 넘길 "업무 인수인계서"** 다.
신입에게 일을 넘길 때 "이건 이렇게, 저건 저렇게" 적어 주듯, AI에게 내 반복업무를 넘기기 위한 **8칸짜리 인수인계서**다.
이 8칸만 채우면 **AI가 그걸 보고 SKILL.md(= 에이전트)를 대신 써 준다.** 담당자는 코드를 한 줄도 쓰지 않는다. **칸만 채운다.**

**왜 8칸인가.** 두 묶음으로 나뉜다.
- **무엇을·왜 (A~E) = 업무를 정한다**. 무슨 일을(A) · 어디가 제일 오래 걸리고(B) · 무슨 자료로(C) ·
  어떻게 되길 바라는지(D) · 어떤 그릇에 담을지(E)
- **어떻게 (F~H) = 일하는 법을 못박는다**. 몇 단계로 도는지(F) · 어디서 사람이 멈춰 확인할지(G) ·
  판단 기준은 숫자로 뭔지(H)

**칸별로 한 줄 질문과 이유**
| 칸 | 한 줄 질문 | 왜 필요한가 |
|---|---|---|
| **A 업무** | 무슨 반복업무를 자동화할까? | 대상이 없으면 시작을 못 한다 |
| **B 병목** | 그 일에서 어디가 제일 오래 걸려? | 자동화가 노릴 핵심 지점 |
| **C 데이터·레퍼런스** | 입력 1개 + 잘된 결과 3개 | ★완성도가 여기서 갈린다. AI가 베낄 '정답 견본' |
| **D 맥락·시도·기대** | 지금 어떻게 / 뭘 해봤고 / 어떻게 되길? | 에이전트가 향할 목표 |
| **E 그릇** | 스킬·에이전트·웹앱 중 무엇? | 만드는 형태를 정한다 |
| **F 스텝** | 5~7단계로 쪼개면? | 에이전트가 도는 순서 |
| **G 게이트** | 어디서 사람이 멈춰 확인할까? | 배포·제출·외부 공개 사고를 막는 안전장치 |
| **H 판단 룰** | 판단 기준을 숫자로? | 사람마다 다른 판단을 일관되게 |

**채우는 순서.** 위에서 아래로 **A → H**. 한 번에 다 안 채워도 된다. 막히는 칸에서 멈추면 스킬이 질문으로 같이 채워 준다.
**가장 중요한 칸은 C다.** '말'이 아니라 **'파일'**을 모으는 칸이다. 잘된 결과물 3개가 곧 AI의 목표가 된다.
대행사에서는 여기에 하나가 더 있다. **수주한 제안서와 떨어진 제안서를 같이 모으는 것**이다.
왜 됐고 왜 안 됐는지가 붙어야 AI가 "잘된 결과"의 기준을 배운다.

## ✅ 완성도 자가 점검 (모두 ☑ 되면 SKILL.md로)
- [ ] A에서 고른 업무의 병목을 **한 문장**으로 말할 수 있다
- [ ] C의 **로우 데이터 1개 + 잘된 결과 3개**를 실제로 모았다
- [ ] D **세 문장**이 구체적이다 (주기·파일·시간·게이트 포함)
- [ ] E 그릇을 정하고 근거를 댈 수 있다
- [ ] F 스텝이 **5~7개**, 각 스텝에 입력·출력·담당이 있다
- [ ] G **사람 컨펌 게이트**가 최소 1개 있다
- [ ] H **판단 룰**이 숫자로 적혀 있다
- [ ] 안전 규칙 다섯(읽기 우선·마스킹·사람 확정·사실 확인·저작권)을 확인했다
