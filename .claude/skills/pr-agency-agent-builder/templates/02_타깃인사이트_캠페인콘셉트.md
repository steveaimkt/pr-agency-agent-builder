# 트랙 02 · 타깃 인사이트·캠페인 콘셉트 기획

> 대행사에서 자주 나오는 업무 · "타깃 인사이트·캠페인 콘셉트 기획" (많이 고르는 순서 2위)
> 갈래 · 기획 · 권장 그릇 · **에이전트**

## 병목 · 어디서 시간이 가나
- 클라이언트 브리프와 경쟁사 메시지를 읽고 타깃을 정의하는 데, 자료를 오가며 시간을 쓴다.
- 인사이트 한 줄을 뽑기까지 브리프·리서치·과거 캠페인을 여러 번 왔다 갔다 하며 다시 읽는다.
- 콘셉트 후보를 여러 안 만들 때마다 근거 자료를 다시 찾아 붙이느라 같은 작업을 반복한다.
- 담당자마다 인사이트를 뽑는 기준이 달라서, 회의에서 다시 설명하고 합의하는 데 시간이 든다.
- IMC 캠페인처럼 채널이 여럿이면, 채널마다 메시지를 다시 손보느라 같은 콘셉트를 여러 번 매만진다.

## 입력 / 출력
- **입력** · 클라이언트 브리프, 경쟁사 메시지 자료, 팩트시트, 채널 가이드, 브랜드 보이스
- **출력** · 타깃 정의, 인사이트 목록, 콘셉트 후보 3안, 메시지 하우스
- 콘셉트 후보 문서는 안 이름, 한 줄 설명, 근거 자료, 톤 넷으로 만든다.
- 메시지 하우스는 핵심 메시지, 지지 메시지, 채널별 톤 세 층으로 그린다.

## 판단 룰 (숫자로 못박는다)
- 콘셉트 후보는 3안. 각 안마다 근거 자료 2개 이상을 붙인다.
- 인사이트 한 줄은 브리프나 리서치 자료에서 문장으로 확인되는 것만 쓴다. 확인 안 되면 [FACT-CHECK]로 남긴다.
- 메시지 하우스의 핵심 메시지는 1개, 지지 메시지는 3개를 넘지 않는다.
- 경쟁사 메시지와 문구가 70% 넘게 겹치면 콘셉트 후보에서 뺀다.
- 타깃 정의는 인구통계 한 줄과 태도·행동 한 줄, 총 두 줄을 넘지 않는다.

## 스텝 초안 (5~7)
| 스텝 | 입력 → 처리 → 출력 | 담당 |
|---|---|---|
| 1 | 클라이언트 브리프 → 핵심 정보를 뽑는다 → 브리프 요약 | AI |
| 2 | 브리프 요약 + 팩트시트 → 타깃을 정의한다 → 타깃 정의 | AI |
| 3 | 타깃 정의 + 경쟁사 메시지 → 겹치지 않는 지점을 찾는다 → 인사이트 목록 | AI |
| 4 | 인사이트 목록 → 콘셉트 3안을 짠다 → 콘셉트 후보 3안 | AI |
| 5 | 콘셉트 후보 → 사람이 하나를 고른다 → 확정 콘셉트 | 사람 |
| 6 | 확정 콘셉트 + 브랜드 보이스 → 메시지를 쌓는다 → 메시지 하우스 | AI |
| 7 | 메시지 하우스 → 채널 가이드에 맞춰 정리 → 채널별 적용안 | AI |

## 사람 개입 게이트
- 콘셉트 3안 중 최종 1안을 고르는 자리. 사람이 고르지 않은 콘셉트는 다음 단계로 넘어가지 않는다.
- 클라이언트 외부 공유 전. 인사이트에 [FACT-CHECK]가 남아 있으면 공유하지 않는다.
- 메시지 하우스가 브랜드 보이스와 어긋나지 않는지 담당자가 마지막에 눈으로 확인한다.

## 도구
- **읽기** · docx·pdf 읽기 스킬로 브리프와 팩트시트를 연다
- **만들기** · 중간 산출물은 `.md` 로 만든다. 고치기 쉽고 다시 돌리기 쉽다
- **내보내기** · 마지막에 형식을 고른다. 이 트랙에 맞는 것은 **파워포인트** 이다
  | 고르면 | 무엇으로 | 언제 |
  |---|---|---|
  | 파워포인트 | 공식 스킬 `pptx` | 발표하거나 고객사에 보고할 때 |
  | 워드 | 공식 스킬 `docx` | 문서로 넘기고 상대가 고쳐 써야 할 때 |
  | 엑셀 | 공식 스킬 `xlsx` | 표와 숫자가 본체일 때 |
  | 웹 화면 | `tools/md2html.py` | 빨리 보고 링크로 돌려볼 때 |
- **검산** · 인사이트 목록의 문장마다 출처 자료 이름을 옆에 적어 둔다. 콘셉트 후보와 경쟁사 메시지를 나란히 놓고 겹치는 문구가 있는지 본다

## 샘플 자료 · 내 파일이 없으면 이걸로 시작한다
- `input/리서치/client-brief.md` · 클라이언트 브리프 견본. 타깃 정의의 출발점
- `input/리서치/competitor-messages.md` · 경쟁사 메시지 모음. 인사이트를 뽑을 때 대조 자료
- `input/리서치/media-coverage-sample.json` · 매체 보도 샘플. 시장 맥락을 채운다
- `input/콘텐츠/brand-voice.md` · 브랜드 보이스. 메시지 하우스 톤을 맞춘다
- `input/콘텐츠/campaign-brief.md` · 캠페인 브리프 견본. 콘셉트 후보를 짤 때 정답 견본
- `input/콘텐츠/channel-guide.md` · 채널 가이드. 채널별 적용안을 만들 때 쓴다
- `input/콘텐츠/fact-sheet.md` · 팩트시트. 타깃 정의의 숫자 근거
- `input/교체용/client-brief-2.md` · 2회차 실습용 교체 브리프
- `input/교체용/campaign-brief-2.md` · 2회차 실습용 교체 캠페인 브리프
- `input/교체용/fact-sheet-2.md` · 2회차 실습용 교체 팩트시트

## 자주 나오는 함정
- 인사이트를 뽑을 때 담당자의 느낌으로 한 줄을 만드는 것. 자료 문장으로 확인되지 않으면 [FACT-CHECK]로 남긴다.
- 콘셉트 3안이 서로 다른 톤이 아니라 문구만 바꾼 같은 안이 되는 것. 근거 자료가 다르면 안도 달라진다.
- 경쟁사 메시지를 참고만 하려다 문구가 그대로 옮겨지는 것. 겹침 비율을 계산으로 확인한다.
- 타깃 정의가 너무 넓어 인사이트가 뻔한 말이 되는 것. 두 줄 안에서 좁혀야 날카로워진다.
